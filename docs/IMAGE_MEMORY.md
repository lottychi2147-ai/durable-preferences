# 圖像記憶研究：歡迎一起討論

## 起點

我們想研究的不是「讓使用者看懂一張漂亮的熱度圖」，而是：

> 經驗能否形成一份可攜、可更新、可由 AI 使用的圖像化記憶資產？
> 即使逐次事件細節已經不在，系統仍保留那些經驗造成的長期傾向。

現在的 v0.2.0 提供結構化狀態與 atlas，作為可運算、可檢驗的基準。
接下來的圖像方向必須證明自身優勢，不能把基準系統的成績當成視覺讀取的成績。

## 三條路線，分開比較

| 路線 | 讀寫方式 | 已完成？ | 待回答的問題 |
|---|---|---|---|
| A. 結構化狀態＋色圖 | 程式寫狀態；模型讀 JSON；人或模型可另看 atlas | 已有原型 | 長期偏好形成與使用是否可靠？ |
| B. 圖片原生 codec | 明確 schema 把概念 ID、狀態與版本編入像素；程式解碼 | 否 | 檔案大小、更新局部性、校驗與可攜性有無實際優勢？ |
| C. 視覺模型直接讀圖 | 模型用圖及圖例判斷偏好，再交由受控程式更新 | 否 | 換模型、縮放、壓縮與色差後能否讀對？成本是否優於 A？ |

不把 B 的精確程式解碼與 C 的模型感知混為一談。
圖像變小不代表語意資訊免費，也不代表模型輸入 token 一定減少。

## 開放問題

1. **色彩語法：**正負、未知、中性、熟悉度、信心與暫時抑制，應如何分離？是否需要圖例與文字通道？
2. **概念身份：**圖片重新排版、增刪節點後，如何維持穩定 concept_id，而不靠像素位置猜身份？
3. **局部更新：**改一項偏好是否要重繪整張圖？可否用分塊、稀疏圖層或版本差分？
4. **學習與遺忘：**原文淡去、偏好保留，與使用者真正要求刪除，如何區分？舊圖副本會不會帶回已忘記的偏好？
5. **資訊品質：**如何讓稀疏好評累積，又不把習慣、被迫、玩笑或模型自述當成喜歡？
6. **圖結構：**關聯邊是否能改善情境化推薦？如何避免從一家店負評錯誤傳播到整類食物？本版尚無此功能。
7. **可攜與私密：**圖就是資料；截圖、公開展示與分享會不會洩露個人偏好？遮住文字是否真的移除了資料？

## 建議的對照實驗（尚未執行）

以完全相同的合成事件與累積狀態，對照 A / B / C。
固定輸入預算、任務、概念字典與版本；記錄預先訂好的成功門檻，不為過測試臨時改題。

- 任務：推薦、避免項、當次例外、更正後讀取、跨年稀疏學習、重啟接續。
- 精度：概念對應正確率、有效偏好方向、未知判斷、例外遵循、更正延遲。
- 成本：端到端延遲、輸入大小、模型呼叫／輸入成本、寫入與重繪成本。
- 魯棒性：縮放、色彩轉換、壓縮、截圖裁切、損毀、不同模型。
- 安全：跨使用者隔離、提示注入、刪除傳播、過時圖像重放。

**負面結果一樣有價值。** 如果圖像讀取沒有優勢，保留 A 作核心，而把圖用於檢查與協作，也是合理結論。

## 如何參與

使用「圖像記憶提案」Issue 格式，或參照 [RFC-0001](RFC-0001-image-memory.md) 開啟討論。
提出目標、最小合成例子、編碼規則、對照組、預期風險與可量測指標即可，不必先完成整套程式。
不投稿真實私密聊天、個人記憶庫、金鑰或他人資料。
