# 方法方案：偏好是可更新的狀態，不是每次重讀的歷史

**本文件描述 v0.2.0 實際程式。新研究提案另見 IMAGE_MEMORY.md。**

## 1. 問題與產品邊界

目標是解決超長時間互動後，AI 容易遺失飲食口味與互動風格等傾向。
我們容許逐次事件原文到期，但要求形成的偏好在新聊天與重啟後仍可取用。
同時，偏好必須能被新經驗逐步改變，或由使用者明確更正。

不是完整人格診斷，不是意識模型，不是影像隱寫，也不是萬用 RAG 替代品。
日期、金額、承諾、過敏等精確或硬性限制，不應交由喜好分數裁決。

## 2. 記憶的三個角色

| 角色 | 內容 | 生命週期 |
|---|---|---|
| Stable | 目前已形成的長期傾向 | 不因沉默清零；可更正、反轉、忘記 |
| Candidate + long_evidence | 尚未鞏固的新方向 | 短期候選按日曆過期；慢速 pending 按事件數有界 |
| Overlays | 這次、今天、特定 session 的例外 | 有期限，到期後不再覆蓋 stable |

每個節點定址為 `owner_id / subject_id / namespace / scope / concept_id`。
標籤只是顯示文字，不用字面相似度擅自合併概念。
目前的「圖」是可定址的概念狀態集合與其色圖投影；**沒有實作概念邊傳播的完整圖神經模型**。

## 3. 從訊號到狀態

`explicit` 與 `correct` 是明確概括或更正，立即寫入 stable。
`feedback` 是一次體驗評價，進入累積機制。
`mention` / `choice` 只增加 familiarity，避免把方便、被迫或重複提及當成喜愛。
`temporary` 寫短期覆蓋，不修改 stable。

輸入必須由宿主正確標出 `role=user`、`mode=real`、來源、主體及原始時間。
引擎可以拒絕標為玩笑或轉述的資料，**不能憑此聲稱已能自動識別反諷**。

## 4. 快慢雙路徑

### 4.1 快路徑

60 日候選窗口；EMA α=0.35。
四個獨立 UTC 日的同方向評價可觸發鞏固。過期只丟短期候選。

### 4.2 慢路徑

保存最多 16 組尚未消費的獨立日摘要 `(day, value)`，不按日曆過期。
至少 4 組、至少 75% 同向、平均方向與多數一致，才鞏固。
中性有自己的語意；正負互相抵銷但彼此衝突，不等於已確認中性。

這修正了舊版的失敗：每季一次好評，上一條在 60 日後消失，十年也湊不滿四條。
新版按有效體驗累積，所以等待本身不抹掉證據。

### 4.3 一次消費與更新

```python
# 概念性偽碼；完整可執行程式在 scripts/memory_core.py
if fast_ready:
    target = fast_ema
elif slow_ready:
    target = slow_mean
else:
    keep_pending()

if ready:
    stable = target if stable is None else stable + 0.40 * (target - stable)
    clear_fast_and_slow_pending()
    preserve_last_counted_day()
```

同一個事件不會同時在快慢路徑重複鞏固。
歷史累積質量只用於摘要與稽核，不讓早期 1,000 票永久壓住後來 12 次反向體驗。
目前使用固定學習率，不以「信心滿格」凍結後續學習。

## 5. 讀取與宿主

`compile` 讀核心風格及指定 scope，套用當下例外，按預算產生 JSON ContextPacket。
`concept_ids` 可點名相關概念。state_index / scope_stats 在寫入交易中同步更新，
避免每輪把整個 scope 載入後再排序。

仍有取捨：輸出預算有限，`omitted_count` 必須保留；大量同時生效的 overlays 尚需額外壓測。
完整 `get` 是列舉，不適合冒充同等成本的快路徑。

**宿主每輪先讀偏好，才呼叫模型；資料載入成功與模型最後有沒有遵循分開驗證。**
Skill 可供不同宿主掛載，但本包不自動安裝雲端 Hooks、MCP 或帳號授權。

## 6. 圖與數值的對應

領域 scope 經固定 SHA-256 映射色相；飽和度對應傾向強度的絕對值。
正負、中性、未知及 historical 另用文字和數值標明。
顏色不是通用心理量尺，讀取不依賴視覺模型猜測。

atlas 與 JSON 都來自同一份狀態。更動圖形設計不得悄悄改變偏好資料。
圖像原生編碼、關聯邊、模型直接讀圖，都應先提出格式與對照實驗，再加入核心。

## 7. 更正、刪除與歷史缺口

- 更正：立即改 stable，重置更正前候選與學習期。
- 忘記：移除該概念狀態與證據，保留雜湊刪除水位及去重憑證。
- 原文清理：只清 journal，不等於忘記偏好，也不是完整個資刪除。
- 去重：完整 SHA-256 二進位儲存，精確去重，儲存仍隨事件量成長。
- 移轉：只還原到空主體；舊快照不能覆蓋現有刪除紀錄。但全新環境只有舊快照時，無法得知之後的刪除。
- v0.1.x 遷移：複製到 schema 2，不改原庫。已丟失的季度好評不從熟悉度猜回來，標 `legacy_gap=true`。

## 8. 不確定性與研究問題

4、16、75%、0.40、60 天及 365 天新鮮度都是本版啟發式。
UTC 日不等於真實獨立事件；使用者可能一天有兩次獨立體驗，也可能兩天重述同一件事。
50% 方向噪聲仍可能讓狀態過度確定。需要固定反例、保留失敗、跨種子測試及真實訊息評測。
